# blyg-ios (all agents)

*Blyglet (called Blyg until 2026-11-22): a little iPhone app for posting to blygs and reading them (the Blygger protocol, blygger.org). Only the name people see changed: the bundle ID, repo, targets, scheme, folders and the on-phone library folder keep `Blyg` on purpose (see `BUILD.md` Decisions). Built for the Blygger hackathon, 2026-11-20 to 11-27. Layers on Jenna's global rules and `ios.md` in the `djinna/agents` repo; this file wins where they differ. One bullet per line; no hard wraps.*

- **Status:** current state, versions and decisions are in `BUILD.md`. The working plan is `PLAN_2026-11-20.md`. It's local only and kept out of git through `.git/info/exclude`, because it names work accounts. Its section 0 holds Jenna's answers and wins. Build in the order of its section 6, stopping at each ✓ to show Jenna screenshots in light, dark and the largest text size.
- **This repo is public from the first commit.** Never commit tokens, `.env`, personal data, or anything naming Jenna's work accounts or work projects. Before every commit, grep the staged diff (`git diff --cached`) for tokens (`gho_`, `Bearer`, `token`), `.env` and work names. A public history can't be cleaned.
- **Hackathon:** only commits on `main` count, and merge commits don't, so commit straight to `main`, small and often. Commits count until the end of 2026-11-27 Pacific (03:00 ET 11-28). Author: Jenna's git identity; agent commits add `--trailer "Agent: claude-code" --trailer "Model: <provider>/<model>"`.
- **Apple:** personal team `K24RHPX75P` only. Bundle ID `net.jdbb.blyg`, fixed for good; extension IDs go under it. The team ID lives only in `project.xcproj` and `scripts/ExportOptions.plist`, never in code: the Keychain group comes from the entitlements' `$(AppIdentifierPrefix)`. Forks retarget with `scripts/use-my-team.sh`.
- **Simulator:** `iPhone 18 Pro`, named (never `booted`). Jenna's phone: see `xcrun devicectl list devices`.
- **Build and test:** `xcodebuild -scheme Blyg -destination 'platform=iOS Simulator,name=iPhone 18 Pro' -derivedDataPath DerivedData.noindex test > DerivedData.noindex/test.log 2>&1` (unit tests plus UI tests). Never pipe it through `head`.
- **Project:** `Blyg.xcodeproj/project.xcproj` (Xcode 27's JSON format; Xcode wrote it directly). Targets `Blyg`, `BlygShare` (Share extension, `net.jdbb.blyg.share`), `BlygTests` (Swift Testing) and `BlygUITests` (XCTest). New files under those folders join their target automatically. `Shared/` (posting client, Keychain tokens, photo prep) is compiled into both the app and the extension; keep it free of app-only code. Swift 6, iOS 18.0+, iPhone only. The shared scheme is in `xcshareddata/xcschemes/`. Close the project in Xcode before an agent moves files or edits `project.xcproj`.
- **Privacy manifest:** `Blyg/PrivacyInfo.xcprivacy`. Add a reason whenever code starts using a required-reason API (UserDefaults, file timestamps and others).
- **Scripts:** `scripts/phone.sh` builds, installs on Jenna's iPhone and checks the app is still running 5 s later (phone unlocked; never uninstall). `scripts/testflight.sh` archives and uploads: ask first, commit first, and bump `CURRENT_PROJECT_VERSION` in every target, the Share extension included. `scripts/ExportOptions.plist` allows external testing (`testFlightInternalTestingOnly` false; see `BUILD.md`).
- **Ask Jenna before** creating a VM, uploading to TestFlight, adding testers or submitting for review.
- **Never change the live blyg:** blyg.jdbb.net and its VMs (`jd-blyg`, `jd-blyk` on exe.dev) are read-only for agents. From 2026-11-20, Jenna may connect her own phone's app to blyg.jdbb.net and post from it. Agents still never post there, hold its token, or test against it; all testing uses the sandbox VM `blyg-sandbox`.
- **Tokens:** only in the Keychain (app) or a gitignored `.env` (scripts). Never in the bundle, logs, docs, tests or commits.
- **Sandbox blyg:** https://blyg-sandbox.exe.xyz/ on exe.dev VM `blyg-sandbox`, Rex host `blyg-sandbox`. It runs unmodified Studio with `wrangler dev`, and its setup note is `~/BLYG-SANDBOX.md` on the VM. The owner password is in `~/.config/blyg/secrets.env` on the VM: never print it. The sandbox token is `BLYG_SANDBOX_TOKEN` in this folder's gitignored `.env`. Load it with `set -a; . ./.env; set +a` and never echo it.
- **API:** Blygger Studio's `openapi.json` is the source of truth. The REST API is at `{mount}/api` (since Studio 0.49.12; the old domain-root `/api` returns 404 on path-mounted blygs). Take each blyg's API URL from what it advertises (its capabilities or OpenAPI), but use it only when it's https on the blyg's own host and port; otherwise use `{origin}api`, so the token never leaves the blyg (`StudioClient.trustedAPI`). A blyg that isn't https can be read but never gets a token. Hand-write a small Swift client with names that match it. Before writing a call in Swift, try it on the sandbox with Studio's JS SDK from Node.
- **Stack:** SwiftUI, Swift 6, iOS 18+, Apple frameworks only. A package needs Jenna's OK in `BUILD.md` Decisions.
- **Backups:** `git push` sends to GitHub, then to a bare copy on the sandbox VM (`~/backups/blyglet-ios.git`; two push URLs on `origin`). If the VM is down, the push reports an error after GitHub has already taken the commit: check `git ls-remote https://github.com/djinna/blyg-ios.git main` before assuming it didn't land, and push again later. The local-only files (plan, handoffs, `workdocs/`) are backed up by `~/jd-projects/blyglet-private/backup.sh` to the private repo `djinna/djinna-blyglet-private` and the VM. It never copies `.env`.
- **Work files** (screenshots, scratch notes, one-off scripts) go in `workdocs/` in this folder, never `/tmp` or the scratchpad, so Jenna can open them by a short path. It's excluded through `.git/info/exclude` and never committed. `workdocs/shots.sh` takes the standard light, dark and largest-text screenshots.
- **Records:** `AGENTLOG.md` (one entry per session, newest first) and `BUILD.md` (status, versions, decisions, lessons), per the global rules.
- **Closing a substantive session:** after the records are committed and pushed, run `~/jd-projects/blyglet-private/backup.sh` and say in the summary that it ran (or why it didn't).
